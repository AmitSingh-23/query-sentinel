# DECISIONS

Non-trivial implementation decisions and the reason for each.

| # | Decision | Reason |
|---|----------|--------|
| D1 | Build + verify in a Linux workspace with a native PostgreSQL 16.15 cluster (HypoPG 1.4.0 from the Ubuntu archive, `shared_preload_libraries=pg_stat_statements`). Docker daemon was not available in the build sandbox. | The spec requires real verification against PG16/HypoPG; native install gives identical extension behaviour. Docker files are validated with `docker compose config` only (see VERIFY.md). |
| D2 | App connects as least-privilege role `qs_app` (SELECT on business tables, write only on `optimizer_meta`, member of `pg_read_all_stats`). Verified: INSERT on `tenants` and CREATE INDEX on `orders` are denied, HypoPG works. | Section 11 + R10: enforce the boundary in PostgreSQL, not only in prompts. |
| D3 | `GRANT SELECT ON hypopg_list_indexes TO qs_app` added. | Verified live: the view is not readable by non-owners by default (`permission denied for view hypopg_list_indexes`). Column is `index_name`, not `indexname`. |
| D4 | EXPLAIN runs inside `BEGIN READ ONLY` + `SET LOCAL statement_timeout`. Only `SelectStmt` (incl. read-only CTEs) passes the gateway. | Defence in depth: even if the gateway were bypassed the transaction cannot write. |
| D5 | Literal parameterisation numbers `$n` in source order (sorted by AST `location`); each literal gets its own number. The vault keeps `$n -> SQL literal text` privately so rewritten SQL can be EXPLAINed with the original values on the trusted side. | Spec example ($1,$2,$3) + needed for sandbox EXPLAIN of rewrites. |
| D6 | Reverse translation of LLM/agent SQL/DDL uses exact pseudonym token replacement (`tbl_/col_/als_` + 6-12 hex) followed by a pglast re-parse. Unknown pseudonyms => rejection. | Pseudonyms are unique tokens; parse after translation guarantees syntactic validity. |
| D7 | LLM access implemented via plain HTTPS (httpx) for `gemini` and `openai`-compatible providers; default `LLM_PROVIDER=none` uses deterministic agents. `mock` provider for tests. | Spec allows a configurable provider; avoids an unverified vendor SDK dependency. Model-mode transparency reports which path ran. |
| D8 | GNN readout: GCNConv(F,32)-ReLU-GCNConv(32,16)-ReLU-global_max_pool-Linear(16,4). | Spec layers kept; a graph-level readout is needed to classify a whole plan. Max-pool keeps the dominant (bottleneck) operator signal. |
| D9 | GNN training labels come from a synthetic PostgreSQL-shaped plan generator whose scenario defines the bottleneck class (+ noise). Held-out evaluation reported; also evaluated on real EXPLAIN plans from the demo DB labelled by the analytic fallback (agreement metric, not accuracy against ground truth). | No public labelled corpus is available offline; this is stated in README limitations. |
| D10 | RL = tabular Q-learning, hierarchical (R7): Q_high[state][ADD_INDEX/REWRITE_SQL/PARTITION/SHARD_ADVISORY/NO_CHANGE] and Q_low[state][abstract candidate signature]. Episodes are multi-step (up to 3 actions, hypothetical indexes accumulate). Trained against live HypoPG planner costs on workload templates; held-out templates for evaluation. | Genuine RL with real (planner-estimated) reward, generalising via abstract signatures rather than raw identifiers. |
| D11 | Partitioning / sharding actions get zero validated benefit in the reward (only a risk penalty) because HypoPG cannot validate them. They are always labelled "Advisory - Requires isolated design/benchmark validation". | Section 21/32: never claim physical validation. |
| D12 | SSE implemented with FastAPI `StreamingResponse` (`text/event-stream`), per-request event history replay so late subscribers receive all events. Async variant `POST /api/v1/optimize/async` + `GET /api/v1/report/{id}` added so the dashboard can stream while the pipeline runs. | Section 38; dashboard needs to subscribe before/while the run executes. |
| D13 | PS camera/billet sentence treated as a source defect; no computer-vision subsystem built. Documented in README. | Section 2 source-fidelity note. |
| D14 | pglast 8.4 used (parser of a newer PG major). PG16 SELECT syntax parses identically; DDL emitted by the migration generator is plain PG16 syntax. | Latest pglast available for Python 3.13 in the build env. |
| D15 | GNN node features extended beyond the spec minimum (32 features: + operator family, top-effective-cost indicator, share gap, log plan cost). | First training run generalised poorly to unseen operators (Merge Join) and real plans; GCN smoothing hid which node carried the cost. Measured improvement: unseen-variant accuracy 0.555 -> 0.835, live-plan agreement 0.8 (no tuning on the live plans). |
| D16 | Cost attribution: SubPlan children x parent rows, Nested-Loop inner x outer rows, LIMIT children x (limit cost / child cost). | Raw EXPLAIN totals are per-loop; without this the 319M cost of scenario C was attributed to the outer Bitmap Heap Scan. |
| D17 | Parameterised (pg_stat_statements) statements use `EXPLAIN (GENERIC_PLAN)` (PG16+), executed as a dynamic statement with no bound parameters inside a DO block (revised 2026-10-03). | Binding NULLs through the extended protocol produced a custom plan with cost ~0 (bug found in the upgrade run). Limitation (no skew visibility) is reported per request. |
| D18 | Sandbox keeps a candidate only if the planner used it AND it lowers planner cost by >= 1 % alone; rewrite+index combination evaluated and flagged when worse. | Avoid migrations that add indexes the planner uses but that do not help (observed: covering index used with 0 % gain). Observed: rewrite+FK index worse than FK index alone for scenario C. |
| D19 | Blast-radius size ratio counts only for indexes >= 10 MB (medium) / 50 MB (high). | Unit test showed an 8 KB index on a 100-row table classified "high". |
| D20 | `app/metrics.py` exposes in-process counters + stage durations (JSON + Prometheus text). | Required file in the Section 5 repository structure; gives operational visibility without sensitive data. |
| D21 | ml-pipeline plugin hook (account-level) blocked writing training code; user chose "Skip it for this project". Override recorded outside the repo (/home/claude/ml_pipeline/PIPELINE.md). | User decision; the spec defines the model and training data is synthetic. |
| D22 | Delivery: build/verify in cloud workspace, sync each phase to the user's folder via a tar archive in `.qs_sync/` (new name per phase, extracted with `--overwrite`). | Overwriting an existing file on the device failed silently without delete permission. |
| D23 | Write latency (ms) and partition pruning are simulated on session-private TEMP tables in a transaction that is always rolled back (`app/structural_sim.py`). | PS asks for "simulated increase in write latency" and partition simulation; HypoPG cannot do either. Temp objects are invisible to other sessions and the role cannot write business tables. |
| D24 | Every report carries `zero_exposure_proof` (re-runs the outgoing guard on the exact AI payload) and an `answer` sentence in the PS example style; a DBA copy with real names is restored on the trusted side only. | PS example answer format + "Zero raw data was exposed" claim must be backed by a check, not hard-coded. |
| D25 | Dashboard: Live Log merged into Agents tab, unused Redis vault removed, demo mode (5 core tabs) default, plain-language explainer per tab, author caption removed. | User request: simpler, understandable demo. |
